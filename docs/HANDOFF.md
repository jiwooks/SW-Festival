# 작업 이어받기

이 프로젝트에 새로 합류했거나, 한참 손 놓았다가 다시 잡을 때 읽는 문서.
무엇이 되어 있고 무엇이 남았는지, 어떤 순서로 하면 되는지를 적어둔다.

## 0. 띄워보기

```bash
npm install
cp .env.example .env.local   # LLM_BASE_URL 은 AI팀 엔드포인트가 정해지면 채운다
npm run dev
```

http://localhost:3000 이 뜨면 성공이다.
LLM 엔드포인트가 비어 있어도 화면은 돈다 — 스텁이 응답하게 해뒀다.

## 1. 읽는 순서

| 순서 | 문서 | 왜 |
|---|---|---|
| 1 | `CLAUDE.md` | 서비스가 뭔지, 디자인·카피·접근성 규칙, 화면별 핵심 규칙 |
| 2 | `docs/DECISIONS.md` | 왜 이렇게 만들었는지, **이미 폐기한 안** |
| 3 | `design/screens/*.html` | 화면 12개 원본. 브라우저에서 그냥 열린다 |

`DECISIONS.md`의 "폐기한 안" 표를 꼭 보고 넘어간다. 이미 한 번 논의해서 접은
방향을 다시 꺼내면 시간이 두 번 든다.

## 2. 지금 어디까지 되어 있나

**되어 있는 것**

- 라우트 6개가 다 잡혀 있다 (`/new` `/targets` `/targets/new` `/compare` `/chat` `/report`)
- 랜딩(`/`)이 구현되어 있다
- 디자인 토큰이 Tailwind 유틸리티로 연결되어 있다 (`bg-brand`, `text-muted`, `bg-persona-1` …)
- 공통 컴포넌트: `AppHeader` `PersonaAvatar` `Chip` `AttrRow` `PageFooterBar`
- `src/lib/types.ts` 에 도메인 타입
- 시안 12개 — 로딩·빈 상태·에러까지 다 그려져 있다

**안 되어 있는 것**

- **제품 화면 6개가 전부 제목만 있는 껍데기다.** 시안을 아직 안 옮겼다
- `src/app/api/chat/route.ts` 는 스텁이다. 실제 LLM 호출이 없다
- 데이터 저장이 없다. 새로고침하면 다 날아간다
- 모바일 레이아웃(390) 없음. 데스크톱 1440 만 있다

## 3. 다음 작업 순서

```
02 타깃  →  02-1 직접 만들기  →  03 한눈에 보기  →  01 아이디어 입력
   →  07 로딩 3종  →  04 대화  →  05 리포트  →  06 빈 상태 / 08 에러
```

02 를 먼저 하는 이유는 공통 컴포넌트가 거의 다 거기 있어서다.
`PersonaCard` 를 여기서 만들면 02-1 미리보기와 03 비교표가 그걸 재사용한다.

04(대화)와 05(리포트)를 뒤로 미루는 이유는 상태 관리와 스트리밍이 얽혀 있어서다.
앞의 화면들로 컴포넌트를 충분히 다듬어 놓고 들어가는 편이 낫다.

### 오케스트레이터

`src/app/api/chat/route.ts` 의 스텁을 실제 구현으로 바꾸는 일.
**모델은 AI팀이 정한다.** 여기서는 AI팀이 준 엔드포인트를 호출할 뿐이고,
그 뒤에 어떤 모델이 있는지 가정하지 않는다.

- 토큰 단위 SSE 스트리밍
- 라운드 구조: 첫 반응 → 상호 토론 → 자유 질문
- 쟁점은 대화 중에 미리 태깅해 둔다. 리포트 만들 때 한 번에 뽑으면 품질이 들쑥날쑥하다

AI팀과 맞출 것: 요청·응답 형식(OpenAI 호환 여부), 스트리밍 형식,
순차 발화를 누가 돌리는지, 동시 요청 한도.

## 4. 화면 옮길 때

- 색은 전부 토큰 유틸리티로. **hex 를 하나도 남기지 않는다**
- 반복되는 덩어리는 `src/components/` 로 뺀다
- 데이터는 `src/lib/mock.ts` 에 더미로 두고, 타입은 `src/lib/types.ts` 를 쓴다
- 문구는 시안의 것을 그대로 가져온다. 새로 지어내지 않는다
- 상태가 필요하면 페이지는 서버 컴포넌트로 두고(metadata 때문) 그 부분만
  클라이언트 컴포넌트로 뺀다

합치기 전에 세 개를 돌린다.

```bash
npm run typecheck
npm run lint
npm run build
```

## 자주 틀리는 것

- **Tailwind v4 에는 `tailwind.config.js` 가 없다.** 설정은 `src/app/globals.css` 의
  `@theme inline` 안에 있다. 검색해서 나온 v3 기준 글을 그대로 따르지 말 것
- **다크 모드를 만들지 않는다.** `prefers-color-scheme` 블록을 추가하지 말 것
- **그림자를 쓰지 않는다.** 구분은 1px 테두리로만
- **페르소나에 파란색·초록색을 쓰지 않는다.** 브랜드색과 충돌한다. 정해진 5색만
- **분류 배지를 화면에 노출하지 않는다.** "핵심 타깃", "회의적 타깃" 같은 라벨은 폐기됐다
- **걱정되는 점을 비우지 않는다.** 비면 그 페르소나가 무조건 좋다고만 말한다
- 03 비교표에는 02 카드가 실제로 가진 필드만 쓴다. "인터뷰 경험"처럼 특정 도메인에서만
  말이 되는 축은 넣지 않는다
- 카피에 "인터뷰를 대체한다"는 인상을 주지 않는다
