# 디자인 규칙

색·타이포·레이아웃·접근성·언어 원칙의 단일 출처.
요약은 `CLAUDE.md`에 있고, 이 문서가 전문이다.
색 변수의 실제 구현은 `src/styles/tokens.css`.

---

## 1. 디자인 토큰

`src/styles/tokens.css`가 단일 출처다. 하드코딩한 색을 쓰지 않는다.

### 브랜드 블루
| 토큰 | 값 | 용도 |
|---|---|---|
| `--brand-pure` | `#0277FC` | **로고 마크 전용** |
| `--brand` | `#0A57C4` | 버튼·링크·라벨·말풍선 등 작동하는 모든 요소 |
| `--brand-hover` | `#07408F` | 링크 hover |
| `--brand-on-dark` | `#6BA9FF` | 어두운 배경 위 텍스트 |

`#0277FC`를 본문 텍스트나 버튼 배경에 쓰지 않는다. 흰 글씨와 4.16:1로 AA 미달이다.

### 그린 — 매우 제한적으로
| 토큰 | 값 | 용도 |
|---|---|---|
| `--green-pure` | `#00E021` | **어두운 배경 위에서만.** 그 위 글씨는 반드시 `#101828` |
| `--green-deep` | `#0B7A1B` | 밝은 배경 위 텍스트·칩 |
| `--green-tint` | `#E8FAEC` | 칩 배경 |

`#00E021`은 **페이지 전체에서 2곳 이하**. 많으면 네이버 클론처럼 보인다.

### 중립 — 쿨 그레이. 베이지 절대 금지
```
--bg-base #FFFFFF   --border      #E4E8EE   --text       #101828
--bg-alt  #F5F7FA   --border-card #E1E6ED   --text-2     #344054
--bg-panel #F8FAFC  --divider     #EBEFF4   --text-3     #475467
--bg-bubble #F1F4F8 --border-input #D5DCE5  --text-muted #667085
--bg-th   #EDF1F6   --border-btn  #C8D1DC
--bg-input #FAFBFD
--bg-hl   #F6F9FF
```

`#667085`보다 연한 회색을 텍스트에 쓰지 않는다.

### 다크 섹션 (최종 CTA·리포트 하단 등 부분적으로만)
```
--dark-bg #101828  --dark-card #1D2939  --dark-text #EAECF0
--dark-text-2 #D0D5DD  --dark-border #667085
```
순백 `#FFFFFF` 대신 `#EAECF0`을 쓴다.

### 의미 틴트
```
합의/공통   #0B7A1B on #E8FAEC
충돌/주의   #9A461A on #FDF1E7
다음 행동   #0A57C4 on #EEF4FE (테두리 #C7DBFA)
```

### 페르소나 5색 — 이 다섯 개만 쓴다
```
--persona-1 #14625E  딥틸
--persona-2 #B4551E  주황
--persona-3 #A33A6B  로즈
--persona-4 #7A4E9E  보라
--persona-5 #9A6A16  황토
```
전부 흰 글씨와 4.7:1 이상. **파란색·초록색 페르소나를 추가하지 않는다** (브랜드색과 충돌).

## 2. 타이포그래피

- **본문·제목**: `IBM Plex Sans KR` (300/400/500/600/700)
- **라벨·숫자·수치**: `IBM Plex Mono` (400/500/600)

Mono를 섞는 게 "컨설팅 리포트" 질감을 만드는 핵심 장치다.
eyebrow 라벨, STEP 번호, ROUND 표기, 통계 숫자, 표 헤더에 쓴다.
`letter-spacing: 0.1~0.14em`을 주고 대문자 영문 또는 짧은 한글로.

**금지 폰트**: Pretendard, Inter, Roboto, Arial, Noto Sans

### 스케일 (데스크톱 1440)
```
h1 52 / 1.24 / 700 / -0.028em     본문 L 19 / 1.72
h2 36 / 1.36 / 700 / -0.022em     본문   16 / 1.75
h3-lg 24 / 1.45 / 600 / -0.015em  본문 S 15 / 1.7
h3 17-18 / 1.5 / 600              캡션   13-14 / 1.6
eyebrow 12 / mono / 0.14em
```
제품 화면은 이보다 한 단계 작게 간다 (페이지 제목 26-30px).
모바일(390)은 h1 34, h2 27.

## 3. 레이아웃

- 데스크톱 1440 / 모바일 390 두 벌
- 좌우 여백 데스크톱 80px, 모바일 20px (제품 화면은 70-120px)
- 섹션 상하 패딩 84~92px (모바일 44px)
- radius: 카드 14~16px, 버튼 12px, 작은 요소 9~11px
- **그림자를 쓰지 않는다.** 1px 테두리로만 구분한다
- **다크 모드를 만들지 않는다. 라이트 전용.**

## 4. AI 티 안 나게 — 금지 목록

- 보라·파랑 그라데이션 워시
- 글래스모피즘 (반투명 유리 카드)
- 가운데 정렬 히어로 + 아이콘 3열 기능 카드
- 모든 요소에 똑같은 둥근 모서리와 그림자
- 이모지를 아이콘 대신 사용 (인라인 stroke SVG를 쓴다)
- 왼쪽 컬러 보더 카드
- "~의 힘을 경험하세요" 류 추상적 문구
- 지어낸 통계, 가짜 로고 띠, lorem ipsum

---

## 5. 접근성 — 타협 불가

- 본문 텍스트 대비 4.5:1 이상, 24px+ 굵은 글씨는 3:1
- 터치 영역 44px 이상
- `<div onClick>` 금지. 진짜 `<button>` `<a href>` `<input>`+`<label>`
- 아이콘 전용 버튼에 `aria-label`
- **색만으로 정보 전달 금지** — 페르소나는 색 + 이니셜 배지 + 이름 3중 표시, 의미 칩은 색 + 글자 라벨
- 구분해야 할 색은 색상뿐 아니라 명도도 다르게

---

## 6. 카피 원칙

- 담백하게. 뜬구름 금지
- AI가 만든 조어를 쓰지 않는다: "가장 강한 신호", "반응 온도", "검증 보드" 같은 말 금지
- 사람이 실제로 쓰는 말로: "세 명 모두 공감한 부분", "의견이 갈린 부분"
- 요약보다 인용. 페르소나가 실제로 한 말을 보여주고 해석은 짧게
- 약점을 먼저 인정하는 톤 ("실제 사람의 답변만큼 무겁지 않습니다")
- 모르는 정보는 지어내지 말고 플레이스홀더로: `[개인정보 처리방침]`
